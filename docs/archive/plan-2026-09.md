## Phase 1 — Electron 旧线彻底移除

**目标**：Tauri 2 成为唯一主线，消除「新增桌面能力要改 Rust 命令 + 垫片 + preload」三处同步的长期成本。

**前提确认**：`tauriShim.ts` 是 `preload.js` 的严格超集（多出 `exportTextFile` / `exportBinaryFile`），Electron 的 34 个 IPC 通道在 Rust 侧均有对应命令，**无 Electron-only 能力，功能零丢失**。

### 步骤（按依赖顺序，不可打乱）

1. **零引用叶子，直接删**
   - `dist_electron/`（构建产物，已 gitignore）、`electron/main.bundle.js`（构建产物，已 gitignore）
   - `.npmrc`（只有一行 `electron_mirror`）
   - `打包桌面版.bat`
   - `.gitignore` 去掉 `dist_electron/`、`electron/main.bundle.js` 两条

2. **`package.json` 瘦身**
   - 删顶层 `main`、整块 `build`（electron-builder 配置）
   - 删 scripts：`electron:dev`、`electron:build`、`build:main`
   - 删 devDeps：`app-builder-lib`、`concurrently`、`electron`、`electron-builder`、`esbuild`、`png2icons`、`rcedit`、`wait-on`
   - `allowScripts`：删 `electron@33.4.11`、`esbuild@0.28.1`；**保留 `esbuild@0.21.5`**（vite 传递依赖，装包需跑 install script）

3. **启动脚本改写**（`启动YiziVoice.bat` 现在是 Electron 专用，会 `npm install electron`）
   - `启动YiziVoice.bat:19-29` 改为 `npm run tauri:dev`
   - `启动YiziVoice.vbs` 包装逻辑随之确认

4. **前端解耦**（必须先改引用，再删目录）
   - `main.tsx:9-12`：去掉 `if ('__TAURI_INTERNALS__')` 条件
   - `tauriShim.ts` 注入点 + `configService.ts:6-14`：`getElectronAPI()` 退化为「取已注入的桥」，`isElectron()` 直接删
   - 消费点 27 处 / 11 文件：`TitleBar.tsx`、`theme.ts`、`SettingsDialog.tsx`、`AboutDialog.tsx`、`TutorialDialog.tsx`、`TextToSpeech.tsx`、`storage.ts`、`historyService.ts`、`runtime.ts`
   - `runtime.ts`：删 `'electron'` 分支与 `isTauri()`（全仓无调用方）
   - 死分支删除：`storage.ts:97-104`、`storage.ts:119-124`、`historyService.ts:86`（该处 `file://` 回退还违反「历史音频必须走 asset protocol」的约定）
   - `storage.ts:28-55` 的 `migrateToElectron()` **不是死代码**（localStorage 时代数据迁移），保留逻辑、仅改名

5. **删目录**：`electron/`、`build/`（`build/` 仅被 electron-builder 的 `win.icon` 与 `main.js:582` 引用；Tauri 用 `src-tauri/icons/`，界面 logo 用 `public/icon.png`，互不相干）

6. **文档**（详见调研结论，此处只列处理方式）
   - 整段删：`AGENTS.md` 的 Electron 三节（环境判断 / 主进程构建 / files 配置）、`HEARTBEAT.md`「Electron 旧流程」节、`MEMORY.md` 打包相关节、`SOUL.md` 对应段

## Phase 2 — 历史音频下载

**目标**：历史记录条目（现渲染在 `src/components/LeftPane.tsx`，原 `HistorySidebar.tsx` 已不存在）能下载音频。

**核心约束**：历史音频走 asset protocol，URL 形如 `http://asset.localhost/...`。而 **`asset:` 不在 CSP `connect-src` 内**，前端 `fetch` 会被拦——**不能复用现有前端取数路径**。同时 `downloadUrl` 现已收窄为只接受 `data:` URL。

### 方案（推荐一次 invoke 完成，不引入前端 base64 往返）
1. Rust 新增命令 `export_file_as(source_path, file_name)`：在 Rust 侧读文件 → 弹另存为 → 写盘。
   - `util.rs` 已有 `decode_base64`，**没有 encode**，本方案也无需新增 encode
   - 注册进 `src-tauri/src/lib.rs`（当前 29 条命令）
2. **安全（必须做）**：校验 `source_path` 落在数据根的 `History/` 内，否则该命令就是一个任意文件读取原语。校验复用 `paths.rs` 的数据根解析（注意用户可重定向数据根）。
3. 前端：`storage.ts` 新增 `downloadFromPath(absPath, filename)` 调该命令；`LeftPane.tsx` 历史项加下载按钮（仅 TTS 条目有音频）。
4. ASR 条目当前**根本没有音频落盘**（`saveAsrEntry` 不传音频）。是否给 ASR 也落盘，是独立决策。

### 验收
装包后点历史音频下载 → 弹系统另存为 → 文件可播放；再验证越界路径被拒。

## Phase 3 — 历史记录完整状态还原

**目标**：点击文生音历史条目，**完全还原生成时的界面状态**——一级模式（音频标签控制 / 自然语言控制）、二级模式（一段话描述 / 导演演绎）、各控制参数、prompt、音色、风格、标签、文本，以及对应音频。

**现状**：已有「加载到编辑器」入口，但 `TextToSpeech.tsx:90-100` **只还原 `text` / `voice` / `style` 三项**；`TtsHistoryEntry` 里根本没存模式与 nl 明细。

### 步骤
1. **扩展 `TtsHistoryEntry`（字段全部可选，向前兼容）**
   - 需新增：`ttsMode`（tags/natural）、`nlMode`（paragraph/director）、`nlParagraph`、`nlRole`、`nlScene`、`nlDirection`、`styleValue`、`styleLabel`、`format`、`duration`
   - **语义拆分**：现有 `style` 字段承载的是「组装后的 userPrompt」（`:216-241` 组装），与 tags 模式下选中的 style value 不是一回事。新增独立字段时不要改变旧 `style` 的含义，否则旧记录会还原错。
   - `HistoryIndex` 有 `version: 1` 但 `loadHistory` **从不校验/迁移**（`historyService.ts:13-17` 直接返回 entries）→ 新增字段靠「可选 + `??` 兜底」，不引入 schema 迁移。
2. **写入点补齐**：`TextToSpeech.tsx:281-289` 的 `saveTtsEntry(...)` 传入上述字段。
3. **消费点扩展**：`TextToSpeech.tsx:90-100` 从三项还原扩展为完整还原，顺序：`ttsMode` → nl 明细 → style → 文本 → 展开对应面板。
4. **可选**：`LeftPane.tsx` 条目摘要加模式徽章，便于区分。
5. **验收**：切到自然语言/导演模式、填满角色/场景/指导 → 生成 → 点历史条目 → 逐项比对界面与生成时一致（含模式切换按钮的选中态）。

### 附带议题（建议分开做，不要混进本 Phase）
TTS 页**所有选择状态现在都是纯内存**（`ttsMode` / `style` / `voice` / `text` / nl 草稿 / `openPanel`），刷新即丢；`settings.defaultVoice` 与 `defaultFormat` 已存在但 TTS 页根本没消费（`TextToSpeech.tsx:54` 硬编码 `'mimo_default'`）。「还原历史」与「记住上次选择」是两件事，混在一起会互相干扰。
